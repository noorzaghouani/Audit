🎯 Project Objectives

03 / 09
Deploy an Odoo architecture that is highly available, secure and ISMS-compliant.
  • ✅
    Eliminate all SPOFs : Redundancy at each layer
  • ✅
    Business continuity : Instant automatic failover
  • ✅
    Reduction of interruptions : Minimized RTO and RPO
  • ✅
    Cyber resilience : Protection against outages and attacks
  • ✅
    ISO 27001 compliance : Respect of security controls
  • ✅
    Validation by tests : Real failure simulations

💡 Proposed Solution : Global Architecture

04 / 09
Redundant and segmented architecture in 3 distinct layers :
  • 🔁
    Total redundancy : 2 load balancers, 2 Odoo, 3 databases
  • ⚡
    Automatic failover : Transparent detection and failover
  • 🔒
    Security : HTTPS (443) with upstream firewall
  • 📊
    Monitoring : Continuous health checks

⚖️ Load Balancer Layer (Zone 1)

05 / 09
Intelligent traffic distribution and elimination of the SPOF at ingress.

🔷 HAProxy

  • Distribution of HTTPS traffic to Odoo nodes
  • Proactive failure detection via health checks
  • Prevention of server overload

🔷 Keepalived (VRRP)

  • Management of a floating Virtual IP (VIP)
  • Automatic failover between lb1 (Active) and lb2 (Backup)
  • Guarantee of continuity without external disruption
lb1 (Active / RHEL)
HAProxy + Keepalived (holds the VIP)
⟵ VRRP ⟶
lb2 (Backup / RHEL)
HAProxy + Keepalived (instant recovery)

⚙️ Odoo Application Layer (Zone 2)

06 / 09
Containerized business processing ensuring high availability and isolation.
  • 🐳
    Docker containers on VM : Identical and isolated odoo1 and odoo2 instances
  • 🔗
    Shared database : Single connection to the PostgreSQL cluster
  • ⚡
    Transparent failover : If odoo1 goes down, immediate redirection to odoo2

🔒 Network & Security Layer (ISO 27001)

08 / 09
🔥 WAF (1st defense line) : HTTPS inspection, blocking application attacks (SQLi, XSS, DDoS, brute force).

🛡️ Hardening Linux

  • Disabling useless services
  • Closing unused ports
  • Auditd A.8.15 : Logging
  • Chrony A.8.17 : Clock sync

🌐 Segmentation A.8.22

  • Zone 1 : Load Balancer
  • Zone 2 : Odoo Application
  • Zone 3 : Database
  • Strict inter-zone isolation

🔒 Accès HTTPS A.8.24

  • End-to-end TLS encryption
  • https://erp.tek-up.local
  • Plaintext HTTP traffic forbidden

📊 Test Assessment & HA Validation

09 / 09
Experimental validation of resilience and recovery times upon failure.
Scenario Triggered failure Expected behavior Recovery time
Nominal access None Smooth HTTPS connection to Odoo page Immediate
Active load balancer loss HAProxy shutdown on lb1 Automatic VIP failover to lb2 (auto-return to lb1) < 10 s
Application node loss odoo1 shutdown HAProxy isolates odoo1, requests directed to odoo2 < 10 s
PostgreSQL primary loss Primary machine shutdown Patroni promotes a replica ; Odoo reconnected via router 45 to 60 s
✅ Conclusion : Business continuity guaranteed 100% without human intervention — RTO compliant with ISO 27001 availability requirements.
